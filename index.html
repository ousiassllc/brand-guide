UI カラーガイド

Ousiass 全プロダクト共通のカラー・タイポ・サイズ・UI ガイド（確定）。HEX はクリックでコピーできます。

方針

  • 全プロダクトでひとつの共通パレットを使う
  • ライト / ダークの両方を必須とする
  • UI はほぼ無彩色。静かで余白の多い画面を基本にする
  • プリズム（violet→yellow）はロゴ・キービジュアル専用のヒーローアクセント
  • 状態色は彩度を落とした、ほぼ無彩色寄りの色にする

Do / Don't

Do

  • 背景は bone（ダークはほぼ黒 #050505）、カード／ペインは surface（#141414）、区切りは border。真っ黒 #000 は使わない
  • 主操作は accent（インク色）で示す
  • プリズムはロゴとキービジュアルだけに
  • 状態はアイコン＋文言＋くすんだ状態色で伝える
  • ライト / ダーク両方で確認する

Don't

  • ボタン・リンク・フォームにプリズムを使う
  • 鮮やかな赤・緑などの原色を状態色に使う
  • プロダクトごとに独自パレットを作る
  • ページ背景に真っ黒 #000 / #000000 を直置きする（ダークは --bone = #050505）
  • OS／ブラウザ標準のままのスイッチ・スライダーを出す（ガイドの見た目に合わせる）
  • mute を本文の長文に使う（コントラスト不足）
  • 色だけで意味を伝える

見出しタグと表示サイズ

  • HTML の見出しレベル（h1〜h6）は文書の意味構造、文字サイズは視覚的な役割。2 つは独立して指定でき、一対一の必須対応ではない
  • 上のサイズ表の「用途（例）」は例示。h1 = 40 / h2 = 32 / h3 = 24 などを必須にしない（サイズはスケールのトークンから、画面の役割に合わせて選ぶ）
  • H1 は必須ではない。H1 を置くためだけに大見出しを足さない。既存シェルに埋め込む画面など、H1 なしで h3 / h4 から始まるケースも許容する
  • 小さく見せたいだけならタグは変えず CSS でサイズを調整する。タグは読み上げ（見出しナビ）で自然な文書階層になるよう選ぶ
  • 見出しレベルを飛ばす（例: h2 の次が h4）場合は、文脈上の理由があるか確認する。理由なく飛ばさない
  • 全見出しを一律に縮小しない。ガイドの chrome（Light の細字）もそのまま。コンパクトな管理画面の見本 →（見本の数値は全画面の必須値ではない）

ウェイト

  • Regular (400): 本文・リンク・ナビ・フォーム
  • SemiBold (600): 見出しとボタンのみ（ボタン以外のナビやリンクには使わない）
  • 日本語の長文は行間 1.8 前後、英語の見出しは字間を少し詰めない（0〜0.02em）

スイッチ・スライダー

フォームのオンオフとレンジはガイド見た目必須。OS／ブラウザの標準コントロールをそのまま出さない。スイッチ見本 ／ スライダー見本

スイッチ

  • トラック 36×20、つまみ 14、角丸 full
  • OFF: accent-soft＋border／ON: accent（つまみは bone）
  • フォーカスは --focus の 3px 実線リング（offset 2px。フォーカスリング）
  • ラベルは Regular 15、SemiBold にしない

スライダー

  • トラック高さ 4、角丸 full、未充填は accent-soft、充填は accent
  • つまみ 16 円・surface＋1px border（ダークも同じ構造）
  • accent-color だけに頼らず、track／thumb を明示スタイル
  • 値表示は Mono mute 可

スクロールバー Scrollbar

対象はコンテンツのスクロールバー（overflow: auto の領域）。値を変えるスライダーとは別物で、スライダーの規定（トラック 4・つまみ 16）は適用しない。OS 標準の太く明るいバーと矢印を、静かな UI から浮かせない。縦・横・両方向の操作できる見本 →

見た目（縦横で同じ設計）

  • 矢印（スクロールボタン）なし・細め・透明トラック・角丸 full のグレー thumb
  • カスタム可能な環境では縦幅・横高さ 8pxを基本とする。Firefox 等は scrollbar-width: thin で近似し、全ブラウザで厳密な 8px は保証しない
  • 縦横の交差部分（corner）も透明
  • thumb は通常 --mute（Light #6b6b6e / Dark #8b8b8e）。hover / drag は --ink 側へ強める（Light は少し濃く、Dark は少し明るく）。背景（bone / surface）との視認性を実際に確認する

守ること

  • ネイティブスクロールを使う。独自 JS のドラッグ機構に置き換えない
  • バーを強制的に常時非表示にしない。スクロールできること・操作性を損なわない
  • キーボード（Tab でフォーカス → 縦は ↑↓・PageUp／PageDown・Space・Home／End、横は ←→）、タッチ、ホイール、トラックパッドを維持する。thumb は細くドラッグしにくいので、ドラッグ以外の操作を必ず使える状態にする
  • 対応できない環境があっても、隠すためにスクロール機能を消さない

CSS の適用例と優先関係

@media (forced-colors: none) {
  .scroll {
    /* 標準（Firefox ほか）: thin で近似 */
    scrollbar-width: thin;
    scrollbar-color: var(--mute) transparent;
  }
  /* WebKit / Blink: 擬似要素で 8px にする */
  @supports selector(::-webkit-scrollbar) {
    .scroll { scrollbar-width: auto; scrollbar-color: auto; }
    .scroll::-webkit-scrollbar { width: 8px; height: 8px; }
    .scroll::-webkit-scrollbar-track,
    .scroll::-webkit-scrollbar-corner { background: transparent; }
    .scroll::-webkit-scrollbar-button { display: none; }
    .scroll::-webkit-scrollbar-thumb { background: var(--mute); border-radius: 999px; }
    .scroll::-webkit-scrollbar-thumb:hover { background: color-mix(in srgb, var(--ink) 35%, var(--mute)); }
    .scroll::-webkit-scrollbar-thumb:active { background: color-mix(in srgb, var(--ink) 65%, var(--mute)); }
  }
}
  • 優先関係: Chromium 121 以降は scrollbar-width / scrollbar-color が auto 以外だと ::-webkit-scrollbar を無視する。標準指定を先に書くだけでは 8px・hover / drag の色にならないため、擬似要素が使える環境（@supports selector(::-webkit-scrollbar)）では標準指定を auto に戻す
  • 対応差: WebKit / Blink = 擬似要素で幅・矢印・hover / drag を制御できる。Firefox = thin と色のみで、幅は OS 任せ・hover / drag の色は変えられない・矢印は出ないことが多い
  • OS の制約: macOS やモバイルのオーバーレイ（自動で隠れる）スクロールバーは、擬似要素でカスタムすると常時表示の従来型に変わることがある。OS の設定で常に表示にしている場合も同様に見え方が変わる。これらは仕様上の制限として許容し、スクロール機能自体は維持する
  • アクセシビリティ例外: forced-colors: active（Windows ハイコントラスト等）や OS が太いバーを要求する設定では、上のカスタムを外して OS 側の見やすさを優先する（上の例は forced-colors: none のときだけ適用）

ライト／ダーク切替 Theme switch

ライト／ダークの両対応は必須。切替コントロールの形、初期値、保存、切替時の挙動を共通で決める。色トークンの値（--bone など）は変えず、data-theme で切り替える。操作できる見本 →

採用3 モード（Light / Dark / System）
  • モードは light / dark / system。未選択の初期値は system（prefers-color-scheme に従う）
  • 利用者が light か dark を選んだらブラウザのローカルに保存し、以後は OS の変更で上書きしない
  • system（または未保存）のときだけ matchMedia('(prefers-color-scheme: dark)') の変化にリロードなしで追従する
  • 切替はリロードなし。スクロール位置は維持する。FOUC を避けるため、<head> の同期スクリプトで描画前に data-theme を決める
  • コントロールは Iconoir（sun-light / half-moon / computer）のセグメント。キーボードで操作できる：Tab で入り、←→（↑↓・Home・End）で移動、Space / Enter で選択。選択中は aria-pressed="true"。プリズム色や OS 標準コントロールの直出しはしない。狭い幅（≤480px）ではアイコンのみ（ラベルは読み上げ用に残す）
  • 色のクロスフェードは付けない（prefers-reduced-motion: reduce に関係なく、切替の瞬間は transition を止めて即時に切り替える）。付ける場合もホバー相当（≤180ms）の静かな変化に留め、reduced-motion では色アニメなし
  • 保存キーはプロダクトの名前空間で決めてよい。このガイドは ousiass-theme（ガイド用）を使う。旧デモ用の theme / oth に合わせる必要はない
参考保存先をクッキー等にする案（同一オリジンのローカル保存であることだけを規定する）。
推奨案幅が足りないときの形：アイコンだけ／縦積み／文字付き横並びを、置く場所で使い分ける
  • 決定済み: 「アイコンだけ」と「縦積み」の両方を定義し、置く場所で使い分けること自体は悠太さんの決定。下の使い分けの基準と数値の閾値は推奨案（未確定）
  • 3 形とも同じ 3 モード・同じ theme.js の契約（[data-theme-control] 内の [data-set-theme]・aria-pressed・保存キー ousiass-theme）。role="radiogroup" にはせず、role="group" + aria-pressed のまま。キーボードも同じ（Tab で入り、Space / Enter で選択、←→↑↓・Home・End で移動）
  • アイコンだけ（.seg-icon）: Iconoir の sun-light / half-moon / computer を 20px・stroke-width: 1.5 で 3 つ並べる。ボタンは 44×44px。ラベル（.lb）は視覚的に隠すだけで残して読み上げ用の名前にし、ホバー／フォーカスで吹き出し（ツールチップ）に出す。アイコンだけにして文字情報をなくさない
  • 縦積み（.seg-stack）: アイコン＋ラベル＋右端のラジオ印（18px の円・選択は 6px の点）の縦リスト。1 行 44px 以上、幅いっぱい（最大 280px）。メニューや設定画面向け
  • 文字付き横並び（.seg）: 現行の見た目のまま。タップ領域だけ縦に広げて 44px 以上にする（見た目の高さは変えない）
  • 選択中は色だけに頼らない: --accent 地に --bone 文字の塗り（縦積みはラジオ印の点も）と aria-pressed="true"。forced-colors: active では Highlight / HighlightText の塗りにする
  • フォーカスは採用済みの実線リング（3px・--focus・offset 2px）。切替時の色の transition は付けない（既存どおり）

使い分け 推奨案

置く場所形理由
ヘッダー・ツールバーなど、横一列で狭いアイコンだけ横幅が 3×44px で済む。ガイドのヘッダーもこの形
サイドバー・ドロワー・設定ページ・モバイルメニューなど、縦に余裕がある縦積みラベルが常に見え、選択中が一覧で分かる
幅が十分（横にラベルが 1 行で収まる）文字付き横並び（.seg）現行どおり。ラベルとアイコンの両方で伝わる

切り替えの基準（推奨案）: ビューポートではなくコンテナ幅（または置く場所そのもの）で決める。同じ画面幅でも、ヘッダーはアイコンだけ・サイドバーは縦積み、のように場所で形が変わるため。閾値の目安は、文字付き横並びが 1 行で収まる幅（このガイドの実測で約 300px）。置き場がそれより狭ければアイコンだけ。数値は確定ではなく、アイコンだけのタップ領域 44px を満たしたあとで測り直す。代替: ビューポートの @media (max-width: 480px) でラベルを隠す（このガイドのヘッダーはこの方式。ガイドのヘッダーだけなら足りるが、プロダクトの部品としては推奨しない）。

最小の実装（head に置く）

<script>
(() => {
  const KEY = 'your-product-theme';               // 例。プロダクトごとに決める
  let s = null; try { s = localStorage.getItem(KEY); } catch (e) {}
  const mode = s === 'light' || s === 'dark' ? s : 'system';
  const dark = matchMedia('(prefers-color-scheme: dark)').matches;
  document.documentElement.dataset.theme = mode === 'system' ? (dark ? 'dark' : 'light') : mode;
})();
</script>

上は初期値の決定だけ。System の追従（matchMedia(...).addEventListener('change', …)）・保存・切替ボタン・aria-pressed を含む参照実装は theme.js（このページと tokens-preview が読み込む）。

ボタン・スイッチ・ラジオの状態 States

通常・disabled（opacity .4）・スイッチ OFF/ON・ラジオの見本は変えず、足りない状態を決める。ボタン ／ スイッチ・ラジオ の操作できる見本。

ボタン 推奨案

  • default / hover（色・背景のみ、≤180ms）/ focus-visible / active（リップルは既存）/ disabled（opacity .4・操作不可）/ loading
  • loading: 寸法を維持し、薄くしない。ラベルは透明にして幅を保ち、中央にスピナーを重ねる。aria-busy="true"、クリックは無効（disabled の opacity .4 とは別に扱う）
  • 危険ボタン（dan）: 地・枠・文字は既存の --danger（枠 45% / hover は 10% の薄い混ぜ）。新しい色は作らない

代替: loading をスピナーではなく文言（「保存中…」）のみにする。

スイッチ・ラジオ 推奨案

  • スイッチ: 既定寸法（36×20・つまみ 14）・OFF（accent-soft＋border）/ ON（accent・つまみ bone）は維持。disabled は他部品と同じ opacity .4。つまみの移動と背景の遷移は --motion-base（180ms）の色・位置のみ（バウンス禁止）
  • ラジオ: 18px の円、枠は --mute 1px。選択は --accent 地の中央に 6px の --bone の点。focus は 3px の --focus リング、disabled は opacity .4（ラベルは --mute）

代替: スイッチの disabled を opacity ではなく border / mute だけで示す。

フォーカスリング Focus ring

--focus（Light #4a72d0 / Dark #60a5fa。プリズム blue の薄い借用）の色は変えない。幅は部品の種類で 2 つに分ける。見本と測定（ライブ）→

幅の使い分け 採用

  • 入力系 2px（input / textarea / select / タグ欄）: 枠がすでにあるため、枠を --focus にして 2px の線で囲う（outline: 2px solid var(--focus); outline-offset: -1px）
  • 離散コントロール 3px（ボタン・アイコンボタン・スイッチ・チェック・ラジオ・スライダー）: リングが主要な囲いになるため太くし、outline-offset: 2px で隣接背景との間に余白を置く（Dark の primary は塗り #f5f5f4 と focus が 2.33:1 になるため、余白で背景側に逃がして 3:1 を確保する）（outline: 3px solid var(--focus); outline-offset: 2px）
  • テキストリンク等の既定 :focus-visible は 2px・offset 2px のまま
  • リングは outline で描く（box-shadow は forced-colors で消えるため）

代替: --ring（focus 40%）の halo を残し、内側に 1px の実線 --focus を足す。

非テキストコントラスト 3:1

  • フォーカスインジケータは隣接背景（--bone / --surface / --accent-soft）に対して WCAG の非テキスト 3:1（SC 1.4.11）を満たす
  • 色（--focus）は変えない。足りない場合はリングの置き方（余白・offset・実線）で確保する
  • --ring（focus 40%）は背景に溶けて 3:1 に届かない（Light で約 1.6:1）。単独でフォーカスの目印に使わない（装飾の halo まで）

スピナー Spinner

既存の Feedback 見本（読み込み中）を文章にする。通常面と primary ボタン内の見本 →

寸法・色・周期 推奨案

  • 20px・線 2px・トラック --accent-soft・先端 --accent・0.9s linear
  • ボタン内は currentColor の先端＋ 25% のトラック（primary では先端が --bone 側になり、反転して見える）

代替: 周期 0.8s。サイズを sm / md の 2 段にする。周期を変える場合は #9（pull-to-refresh、0.9s・20・線 2 を前提）と矛盾しないことを確認する（本ガイドは 0.9s のまま）。

reduced-motion

  • prefers-reduced-motion: reduce では回転を止める。先端のアーク・aria-busy・ラベルで処理中であることは残す（モーションの既定「スピナーは維持」と矛盾しない）
  • forced-colors: active ではトラックを透明にし、先端の円弧だけを CanvasText で残す（回転しなくても処理中と分かる）

重なり順とモーダルの影 Layers & shadow

既存の 0–500 の段は並べ替えない。操作できる見本（モーダルの上にメニュー、その上に toast） ／ 影の Light / Dark 比較

z-index 採用

  • --z-base 0 / --z-dropdown 100 / --z-sticky 200 / --z-drawer 300 / --z-modal 400 / --z-toast 500（既存・変更なし）
  • 追加: --z-popup 401（--z-modal + 1）。モーダル内のメニュー／ポップオーバーなど「modal より手前、toast より後ろ」が必要な面に使う
  • dropdown（100）は通常面、popup（401）はモーダルの上、toast（500）は常に最前

既存スケールを 50 刻みで組み直すことはしない。

モーダルの影 採用

  • 影はモーダルだけ（カードは影なし）。--shadow-modal
  • Light: 0 1px 2px rgb(0 0 0 / 6%) ／ Dark: 0 1px 2px rgb(0 0 0 / 40%)
  • Dark の背景 #050505 では黒い影はほぼ見えない。面の分離は --surface と 1px の --border が担う

accent-soft 上の文字とリップル対象

accent-soft 地の補助文字 採用

  • ホバー／選択行など --accent-soft を地にする面の文字は、短い補助テキストでも --ink を使う（または同等に 4.5:1 を満たす色）。--mute のまま置かない
  • 理由: --mute は bone / surface 上では AA 4.5:1 だが、--accent-soft 上では Light 4.29:1 / Dark 4.22:1 と下回る
  • 色トークンの値は変えない。見本（ライブ計算）→

リップルの対象 推奨案

  • 対象: 通常ボタン（pri / sec / ghost / dan）とクローズ等のアイコンボタン。周期は slow 帯 280ms（既存）
  • 非対象: テキストリンク、行型・カード型の選択、タブ、セレクトのトリガ、スイッチ／ラジオ／スライダー（ホバーは色のみ）
  • loading 中のボタンには出さない。reduced-motion では出さない。対象／非対象の見本 →

代替: タブやセレクトのトリガにも付ける。行・カード型に付ける場合は見本で静かな大きさを確認する。テキストリンクには付けない。

forced-colors と reduced-motion の扱い

forced-colors（ハイコントラスト）

  • 色だけで見せていた状態は、システム色に置き換えて残す：スイッチ ON/OFF（Highlight / Canvas）、ラジオ・チェックの選択、スピナーの先端、テーマ切替の選択中（Highlight）
  • フォーカスは outline（forced-colors でも残る）。box-shadow だけに頼らない
  • スクロールバーは既存の規定どおり forced-colors では OS 標準に任せる

prefers-reduced-motion

  • 色の遷移（ボタン・スイッチ・入力）、スピナーの回転、リップルを止める
  • 処理中表示（スピナーのアーク・aria-busy）と状態の変化そのものは残す
